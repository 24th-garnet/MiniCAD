# 返ってきた意見を、要求に突き合わせる表

> **これは建築士の方にはお渡ししません。** 我々の側の道具です。

## なぜ渡さないか

最初はこれを確認表として渡すつもりでいました。**それは間違いでした。**

機能の一覧を渡すと、相手は**仕事をやめて監査を始めます**。「この項目はあるか」
を確かめる作業になり、**「自分の仕事が回るか」という、いちばん知りたいこと
が出てきません。**

**いつもの案件を 1 件、最初から引いていただく。** 詰まったところが、
そのまま直すべきところです。確認表を作ろうとしたとき私が最適化していたのは
「返ってきた意見を `coverage.md` に突き合わせやすくする」こと——
**我々の帳簿の都合**であって、使う方の都合ではありませんでした。

## では何に使うか

意見が返ってきたときに、**それが `coverage.md` のどの項目の話か**を辿るため
の対応表として残します。「使いにくい」で返ってきたものを、要求のどこに
当たるかへ落とす作業に使います。

## 渡す前に済ませてあること

相手に口頭で伝える必要がないよう、**画面側に入れてあります**。

| | どこに |
|---|---|
| **プロモードで開く** | ホストが `mode: 'pro'` で組む。道具 9 本と区画 3 つが最初から見える |
| **書き出せる** | `can_download` の既定を true に（`0010_allow_download.sql`）。いつもどおり使えば最後は持ち帰ろうとするので |
| **何ができないか** | 「使い方」の「いまできないこと」。**指摘の空振りを減らす** |
| **守備範囲** | 「この道具について」。確認申請図書や施工図としての検証はしていないこと |
| **通知が飛ばないこと** | コメントの節。**残せば届くと思われるのがいちばん困る** |
