# 機能の出どころ別一覧

**何が「ワイヤーの要求」で、何が「我々の判断」なのかを分ける表です。**

これまで `status.md`（実装の現在地）と `questions.md`（確認したいこと）の
2 つで足りると思っていましたが、どちらも**出どころを区別していません**。
そのため「一般的な CAD にあるから入れよう」と自分で決めたものが、
いつのまにか「宿題」として一覧に残り続けていました。

| 区分 | 意味 |
|---|---|
| **A** | **ワイヤーに書いてある。** 要求 |
| **B** | ワイヤーには無いが、**一般的な CAD にはある。** 我々が倣って決めたもの |
| **C** | どちらにも無いが、**我々の事情で必要。** 連携・規律・契約 |
| **D** | **要らなくなった／要らないのに、実装してある。** 整理の対象 |

突き合わせたワイヤーは `ワイヤー/クライアント/20_案件詳細_現状図面（作成_編集_削除）_20261005.pptx`
の 8 枚すべてです。番号つきの項目は [questions.md](questions.md) の番号です。

## B. ワイヤーに無く、一般的な CAD にあるもの

### B-1. 倣って入れた（実装済み）

**ワイヤーは求めていませんが、無いと CAD として使えないので入れたものです。**

| 項目 | なぜ入れたか |
|---|---|
| **undo / redo** | 無い作図ツールは使えない |
| **スナップ**（端点・中点・交点・中心・壁・格子・角度） | ワイヤーが書いているスナップは **2D 基準点だけ**。実際に線を引くには他も要る |
| **拘束**（平行・直角・同一直線など） | 引き直しのたびに角度が狂う |
| グリッドの表示と吸着 | 同上 |
| **実寸印刷**・用紙と表題欄 | 「縮尺」が仕様にあるので、紙に出せないと意味がない |
| 線群（細線・太線・極太線） | 1 枚目の「線関連（種類/太さなど）」の互換に必要 |
| 図面ビュー（複数の図面） | レイヤー表が図面ごとに縮尺を持つ形を素直に読むとこうなる |
| **立面図・断面図・展開図の中身** | 入口（立面ビュー）は仕様にあるが、中身の仕様は無い |
| **部屋の自動検出と面積** | 積算に要る |
| トリム・延長・切断 | 製図の基本動作 |
| DXF の Shift-JIS（Jw_cad 用） | 日本の現場で読めないと互換の意味が薄い |

### B-2. 倣っていない（未実装）

| 項目 | いまの判断 |
|---|---|
| **3D の頂点・辺へのスナップ** | **ワイヤーに記述なし。** 候補が爆発する（サンプル間取りで 260 面）ので、絞る仕組みと「どれに吸ったか」の表示で 600〜800 行。**要るかどうかから確認したい** |
| **3D の中で線を描く** | **ワイヤーに記述なし。** 多角形は ※3 と作業面の注記が求めていますが、線は求めていません。`Shape` は 2D（x, y）なので、立った面に引いた線の置き場がありません（高さを持つ線の欄か、新しい実体が要ります） |
| ダブルラインを 1 実体に（マルチライン） | ワイヤーは「二重線を描く」としか言っていない。置いたあとに幅を変える使い方をされるかが分かれ目（28） |
| ハッチング（塗りの柄） | 素材の「柄」（24）と同じ理由で `ctx` の契約が壊れる |
| 文字スタイル・寸法スタイルの共有 | いまは図形ごとに持つ |
| 外部参照（他図面の読み込み） | ホストのライブラリで代えられる |

## C. どちらにも無く、我々の事情で必要なもの

| 項目 | なぜ |
|---|---|
| **ホスト契約**（`mount` / `getScene` / `setScene` / `setComments` / `capture` / `getCamera` / 変更通知） | MiniCAD は**部品**で、madoriba の画面に組み込まれる。境界を決めないと組めない（[host.md](host.md)） |
| **実測 JSON**（`mdr-measures-1`）と**根拠の固定語彙** | [QuantityTakeoff][qt] / [InteriorEstimation][ie] が読む。幾何と数量をそのまま渡す |
| **実行時の依存ライブラリ 0 個** | 組み込み先のビルドを縛らないため。three.js も WebGL も使わない判断はここから出ている |
| **「持っていないことを画面に書く」** | 黙って近いものを出すと、図面が嘘をつく。断り書きと `PRO_NOT_YET` |
| **取り込み・書き出しの損失レポート** | 1 枚目「多少の崩れは許容する」を、**どこが崩れたか言える**形にしたもの |

## D. 要らないのに実装してあるもの

### 消したもの（11 件）

**宣言したきり、本番からもテストからも 1 度も呼ばれていなかったもの**を、
`src` 全体を機械で走査して洗い出しました。残りは 0 件です。

| 消したもの | 置き場 | なぜ死んでいたか |
|---|---|---|
| `fixtureSnapPoints` | `core/fixture.ts` | `core/snap.ts` に "fixture" の文字が 1 つも無く、構造物はスナップ候補に入っていなかった。**直したつもりで効かない罠** |
| `verticalRange` | `core/fixture.ts` | 3D が `baseOf` + `localRange` に移ったあと、**テストだけが呼んでいた**（下記） |
| `distSq` / `rectCorners` / `arcPoint` | `core/geometry.ts` | 作りかけの道具。輪郭は `localOutline`、ブロックは `instanceVertices` が受け持つようになった |
| `leaderTextAngle` | `core/leader.ts` | 常に 0 を返すだけの関数 |
| `hasAttrsFor` | `core/material.ts` | インスペクタは `attrsOf` を直に呼んでいる |
| `pointFromPolar` / `resolveSnapNode` | `core/snap.ts` | 数値入力とノード解決が別の道へ移ったあとの残骸 |
| `saveLocal` | `io/scene.ts` | `saveLocalFile` に寄せたときの取り残し |

**`verticalRange` がいちばん性質が悪いものでした。** 本番は使っていないのに
テスト 5 箇所が呼んでいたので、**本番が壊れてもテストは通ります。**
テストのほうを「本番が立体を置くのと同じ道」（`baseOf` + `localRange` +
`level.floorZ`）に書き換えてから消しました。

### 消さなかったもの（3 件）

| | なぜ残すか |
|---|---|
| `JIS_LINE_WIDTHS`（`core/standard.ts`） | 「この 9 種から選ぶ」と**コメントが言っているのに、何も守っていませんでした。** 消すより、**線群の太さがこの 9 種に入っていること**を見るテストを足して生かしました。外れた値を足した瞬間に落ちます（1:2:4 の比も一緒に見ます） |
| `cylinderH`（水平の円筒） | 3 軸で回るようになって**冗長**ですが、消すと**既存のファイルが読めなくなります**。理由はコメントに書いてあります |
| 楕円 | ワイヤーにあるのは「**長円**」だけ。長円＝小判型なら余分ですが、**読みが決まるまで**残します（15） |
